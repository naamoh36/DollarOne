# DollarOne

ต้นแบบเว็บไซต์ภาษาไทยสำหรับแบรนด์ DollarOne รวมบริการบัญชี/ภาษี และ DollarOne Academy ภายใต้ที่อยู่เว็บไซต์เดียวกัน โทนส้ม ถ่าน และขาวนวล ได้แรงบันดาลใจด้านโครงสร้างจาก borntodev.com และ school.borntodev.com โดยสร้างแบรนด์ ภาพประกอบ และเนื้อหาใหม่

## เปิดใช้งานในเครื่อง

ใช้ Node.js สำหรับตรวจ JavaScript และ Python 3 สำหรับเสิร์ฟไฟล์ ไม่ต้องติดตั้ง dependencies

```sh
cd DollarOne
npm run check
npm run dev
```

เปิด http://127.0.0.1:4173/ หากพอร์ตถูกใช้งาน สามารถเปลี่ยนเป็นพอร์ตอื่นในคำสั่ง Python ได้

## ส่วนที่ทำงานแล้ว

- หน้าแรกและหน้าบริการ 4 ประเภท พร้อมรายละเอียดขอบเขตงาน
- Academy: 6 หลักสูตรตัวอย่าง ค้นหา กรองหมวด และกรองเป้าหมายผู้เรียน
- รายละเอียดโครงร่างหลักสูตรและสถานะการรับรอง
- เพิ่ม/นำคอร์สออกจากแผนที่เก็บไว้ในเบราว์เซอร์
- บทเรียนและแบบทบทวนตัวอย่าง 6 ชุด
- แผนชั่วโมงอบรมส่วนตัว คำนวณความก้าวหน้าและบันทึกตัวเลขบนเครื่อง
- บทความตัวอย่าง 3 เรื่อง คำถามที่พบบ่อย และข้อมูลแบรนด์
- แบบฟอร์มจัดข้อความสอบถามและดาวน์โหลดเป็น TXT โดยไม่มีการส่งข้อมูล
- เมนูมือถือ การนำทางด้วยแป้นพิมพ์ หน้าต่างรายละเอียด และตัวเลือกการล้างข้อมูลในเครื่อง

## ขอบเขตของต้นแบบ

เว็บไซต์ยังไม่เปิดให้บริการจริง ไม่มีระบบสมาชิก ฐานข้อมูลลูกค้า การชำระเงิน การส่งแบบฟอร์ม การนัดหมาย วิดีโอคอร์สเต็ม หรือการออกประกาศนียบัตร

หลักสูตรและระยะเวลาเป็นตัวอย่าง ยังไม่มีเลขอนุมัติ และไม่ให้ชั่วโมง CPD ที่ได้รับการรับรองหรือใช้ยื่นต่ออายุใบอนุญาต ตัวกรองผู้ทำบัญชี/CPA/TA แสดงความเหมาะสมของเนื้อหาเท่านั้น เครื่องมือแผนชั่วโมงใช้เป้าหมายที่ผู้ใช้กรอกเอง ไม่คำนวณเกณฑ์ทางกฎหมายหรือยืนยันการผ่านเกณฑ์

ข้อมูลการเงินในภาพหน้าแรกเป็นข้อมูลสมมติ ไม่มีสถิติลูกค้า รีวิว หรือคุณสมบัติผู้ประกอบวิชาชีพที่แต่งขึ้น ชื่อ DollarOne ยังไม่ได้จดโดเมนตามข้อมูลที่ผู้ใช้ให้มา

## โครงไฟล์

- `dist/index.html`: โครงหน้า เมนู และ footer
- `dist/styles.css`: รูปลักษณ์และ responsive layouts
- `dist/app.js`: ข้อมูลตัวอย่าง การนำทาง และ interaction
- `dist/assets/favicon.svg`: ไอคอนแบรนด์
- `.github/workflows/pages.yml`: workflow เผยแพร่ GitHub Pages จากโฟลเดอร์ `dist`

ระบบใช้ hash routes เพื่อให้ทุกหน้าเปิดได้บน static hosting โดยไม่ต้องตั้ง server rewrite ภายใต้โดเมนเดียว การนำไปทำระบบจริงสามารถย้ายเป็นเส้นทาง `/services`, `/academy`, `/insights` ที่มี server rendering และ metadata แยกหน้าตามความเหมาะสมได้

## การตรวจสอบ

- `node --check dist/app.js` ผ่าน
- หน้าเว็บและไฟล์หลักตอบ HTTP 200
- ตรวจผ่านเบราว์เซอร์: ค้นหา Excel → รายละเอียด → เพิ่มในแผน → บทเรียน → แบบทบทวน → กลับแผน
- ทดลองเป้าหมายส่วนตัว 20 ชั่วโมง มีแล้ว 6 ชั่วโมง แสดง 30% และเหลือ 14 ชั่วโมง และยังเก็บค่าเมื่อโหลดใหม่
- ทดสอบสร้างข้อความติดต่อจากข้อมูลสมมติ โดยไม่ส่งข้อมูลภายนอก
- ตรวจหน้ามือถือผ่าน viewport ใน iframe ความกว้าง 390px รวมเมนูและตัวกรองภาษี

## ก่อนเปิดธุรกิจและ Academy จริง

ยืนยันนิติบุคคล ผู้รับผิดชอบวิชาชีพ ชื่อและโดเมนแบรนด์ ขอบเขตและราคา ผู้สอน หลักสูตร เลขที่อนุมัติและสิทธิการนับชั่วโมง แยกข้อกำหนดผู้ทำบัญชี/CPA/TA ให้ถูกต้อง จากนั้นเพิ่มระบบสมาชิก จัดเก็บเอกสารอย่างเหมาะสม สมัครเรียน ชำระเงิน ตรวจตัวตน/การเข้าเรียน ประเมินผล หลักฐานอบรม ช่องทางติดต่อจริง และนโยบายที่ตรงกับระบบที่ใช้งาน

## พรีวิวสำหรับลูกค้าบน GitHub Pages

เตรียมไฟล์ `.github/workflows/pages.yml` สำหรับเผยแพร่เฉพาะโฟลเดอร์ `dist/` โดยสั่งด้วยตนเองจาก Actions เมื่อ repository มีสิทธิ์ใช้งาน GitHub Pages เส้นทางไฟล์ CSS/JavaScript/icon เป็น relative จึงรองรับ URL แบบ `<account>.github.io/DollarOne/` ได้

หลังเข้าถึง repository และอัปโหลดได้แล้ว ให้ตั้งค่า Settings → Pages → Build and deployment → Source เป็น GitHub Actions จากนั้นตรวจว่า workflow สำเร็จและเปิด URL ที่ deployment คืนมาได้จริง จึงใช้ลิงก์นั้นส่งให้ลูกค้า

GitHub Pages เป็นพรีวิวที่เข้าถึงทางอินเทอร์เน็ตได้ จึงเผยแพร่เฉพาะไฟล์เว็บไซต์ตัวอย่าง ไม่มีเอกสารบัญชีจริง ข้อมูลลูกค้า หรือ credentials ส่วน `.openai/` เป็นข้อมูลโฮสต์อีกบริการในเครื่องและไม่อยู่ในชุดอัปโหลด GitHub

อ้างอิง workflow ต้นทาง: https://github.com/actions/starter-workflows/blob/main/pages/static.yml

Repository: https://github.com/naamoh36/DollarOne

สถานะ: อัปโหลดต้นแบบเข้า repository แล้ว และคง repository เป็น Private ตามคำสั่งเจ้าของ GitHub Pages ยังไม่เปิดใช้งาน เพราะแพ็กเกจปัจจุบันไม่รองรับ Pages สำหรับ repository ส่วนตัว จึงตั้ง workflow เป็นการสั่งด้วยตนเองเพื่อไม่ให้เกิดการเผยแพร่ล้มเหลวซ้ำเมื่อแก้ไฟล์

ยังไม่มีลิงก์พรีวิวออนไลน์ที่ยืนยันว่าเปิดใช้งานแล้ว การเปิดพรีวิวผ่านโฮสต์อื่นต้องยืนยันปลายทางและกลุ่มผู้ชมกับเจ้าของก่อน
